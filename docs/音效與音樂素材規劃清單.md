## 一、 音訊風格調性與整體規範

* **遊戲主調**：日系清新校園動漫風 ＋ 輕科幻電子感（Light Future Beat / Chiptune-infused Kawaii Future Bass）。
* **音樂定位**：
  * 平時保持輕快開朗，強調校園學生的青春探險感；
  * 調查與解謎時轉為清脆低調的思考節奏，營造專注而不沉重的微懸疑氛圍；
  * 故障與警報時採用科技碎拍與失真電子音，帶出 AI 混亂的緊張感；
  * 終章則以抒情鋼琴與柔和弦樂，襯托人機共存的感性哲思。
* **音效標準規範**：
  * **格式推薦**：`.mp3`（相容性最廣，檔案小）與 `.ogg`（高品質網頁循環）。
  * **取樣率/位元率**：44.1 kHz, 16-bit, 128~192 kbps（兼顧音質與載入速度）。
  * **音量平衡（Loudness）**：
    * BGM 統一標準化至 `-16 LUFS`（預設背景播放增益 0.4~0.6）。
    * SFX 統一標準化至 `-12 LUFS`（預設觸發增益 0.7~0.9）。
  * **對話打字機音（Blip）頻率節流**：設有 30ms~40ms 的觸發節流，防止快速輸出文字時瀏覽器音訊通道過載與爆音。

## 六、 Web Audio API 程序化合成備援架構

### 為什麼需要程序化合成備援？
1. **零外部依賴、開箱即響**：在專案剛建立或離線環境下，無須等待音訊檔案下載即可測試。
2. **極致即時性**：對話打字機（Typewriter Blip）若頻繁觸發 HTML `<audio>` 播放標籤，容易發生瀏覽器 AudioBuffer 擁塞或破音。使用 Web Audio API 原生振盪器（OscillatorNode）可以在微秒內生成乾淨、無延遲的音效。
3. **動態表現力**：例如對話打字機可依照 NPC 角色特質動態調整音高（艾瑪沉著高音、阿哲憨厚低音、小智金屬調變音），增加戲劇張力。

### 程序化音訊合成核心邏輯（摘錄）：
```javascript
// Web Audio API 程序化合成範例：打字機嗶嗶聲 (Dialogue Blip)
function playTypewriterBlip(audioCtx, pitch = 580) {
  const now = audioCtx.currentTime;
  const osc = audioCtx.createOscillator();
  const gain = audioCtx.createGain();

  osc.type = 'triangle'; // 三角波，溫潤不刺耳
  // 加上微幅隨機頻率變化 (±30Hz)，讓打字有自然靈動感
  osc.frequency.setValueAtTime(pitch + (Math.random() * 60 - 30), now);

  // 快速指數衰減 envelope (0.025s)
  gain.gain.setValueAtTime(0.08, now);
  gain.gain.exponentialRampToValueAtTime(0.0001, now + 0.025);

  osc.connect(gain);
  gain.connect(audioCtx.destination);

  osc.start(now);
  osc.stop(now + 0.025);
}
```

### 前端呼叫使用範例：
```javascript
import { audioManager } from './js/audio-manager.js';

// 1. 播放背景音樂（自動交叉淡入）
audioManager.playBGM('bgm_campus_daily');

// 2. 觸發對話打字機音（自帶 35ms 節流與防爆音）
dialogueBox.onCharRender = () => {
  audioManager.playSFX('sfx_typewriter');
};

// 3. 玩家選對答案或解開推理
quizButton.onSuccess = () => {
  audioManager.playSFX('sfx_correct');
};

// 4. 小智系統故障跳紅字
systemEvent.onGlitch = () => {
  audioManager.playSFX('sfx_glitch');
};
```
